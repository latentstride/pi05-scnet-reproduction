每个作业独立分配、服务端口、进程组和输出目录，调度依赖为空。P0 只提交一条有新增信息的试次，P1 优先复用历史，P2 先完成 CPU 前置条件。研究上的证据依赖不转成 Slurm 串行依赖。若将来有两项独立获准，可并行排队，无需依赖前一项结束。全局故障只作用于该作业。

CPU 原生首块已跑到第 50 行，后段实测为单指推块而没有抓持。因此 P0 唯一新增的问题是下一次真实观测后，冻结模型能否调整接近与抓持。重复原受保护试次只能重测已复现的候选拒绝。

P0 运行前必须验明作者源代码、冻结 checkpoint 和统计、GPU UUID 与驱动、Vulkan/三路相机、场景/初态、资源余额、终止和进程回收。真实现场验收放在同一分配内。首请求与首动作块逐值可配对时复用 B；不同时同时保留两个哈希、运行参数和差异，单场结果仍可解释，门禁因果对照为 UNKNOWN。

**提前结束也要留证。** 保存初态与首帧、每次真实请求/原始块/RNG 哈希、执行索引、部分动作子步、TCP/指—物实测接触、夹爪及阶段、原生成功谓词、资源账本和退出证据。P2 另外保存每个边界的源/目标 IK、连续性余量、碰撞对和恢复尝试。任何实测场景异常、数据身份错误或进程无法隔离时停止。首块有诊断价值，但一次场景成功或失败都不能估计总体成功率，专家诊断也不计入策略成功。
