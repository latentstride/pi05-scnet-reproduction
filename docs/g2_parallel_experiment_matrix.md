# G2 七项独立闭环实验

基线为 Draft PR #5 的 `a5a67cfb27a787da5562f82e03c3e8d67c257ec3`。场景在运行模型前锁定。按作者专家筛选缓存的分片 0、1、2，各取索引 0。缓存实际返回 `100000`、`200000`、`300000`，三行 `episode_info` 均为空字典。入口仍把实际字典交给作者恢复和语言生成逻辑。每个作业独立原生复位并从模型 RNG seed 0 起步。配置固定 RoboTwin `handover_block`、Aloha-AgileX、原 checkpoint 和 norm stats。

| 作业 | 场景 | 模式与窗口 | 独立研究价值 |
| --- | ---: | --- | --- |
| G1 | 100000 | 作者原生 Fixed H50 | 观察单指推块之后的新观测、模型第二块和抓持进度。历史保护侧在第 43 行停止。 |
| G2 | 200000 | 作者原生 Fixed H50 | 检验另一初态下的闭爪、抬升和交接，提供 G5、G7 的同场景对照。 |
| G3 | 300000 | 作者原生 Fixed H50 | 检查第三个预先选定初态，评估单一场景归因能否推广。 |
| G4 | 100000 | 作者原生 PACE | 对照 G1，检验 PACE 能否在推块前后更早得到新观测。 |
| G5 | 200000 | 作者原生 PACE | 对照 G2，比较接触阶段、查询量、物理步与耗时。 |
| G6 | 300000 | 作者原生 PACE | 对照 G3，检验窗口效应是否依赖初态。 |
| G7 | 200000 | 项目受保护 Fixed H50 | 对照 G2，观察额外门禁会在哪个阶段拒绝，以及能否提供完整安全停止凭证。 |

原生组共用作者 `pace.rollout.run_episode`、原生 `take_action(qpos)`、原生 TOPP 和成功谓词。PACE 使用原始 50×14 输出，选择器是固定源码的 `PaceConfig` 与 `select_horizon`，官方任务校准阈值为 `0.008204944897443056`。原生入口只有资源边界与被动留证。G7 复用现有 FCL 2 mm、实测接触、跟踪、关节、夹爪与安全停止链。命令按原行执行，额外保护可以拒绝动作。冻结配置与源码哈希见[配置目录](../research/g2/parallel-batch/configs/)和[版本锁](../research/g2/parallel-batch/source-lock.json)。

同场景比较首先要求实际 prompt、三路 RGB、14 维状态组成的首请求哈希、JAX 起始及采样 key、首块逐值哈希均匹配。其后窗口变化自然改变观测和动作。G1 与历史 `127510335` 的缓存、checkpoint、初始 RNG 具备配对条件，首交换只能等 G1 真实结果验证。若失败或不匹配，保留两条诊断，门禁的严格配对结论降为 `UNKNOWN`。本批次复用历史证据，不重复提交场景 100000 的保护侧。[配对检查脚本](../research/g2/parallel-batch/summarize_pairs.py)按该规则比较。

只对作者谓词成功记 `SUCCESS`。用尽 800 个动作且无额外干预记 `TASK_INCOMPLETE`。安全停止、资源删失与基础设施故障分别报告；未观察到的阶段记 `NOT_REACHED`，原始预测及实际动作独立判读。三对场景是配对诊断，不用于估计总体成功率。
