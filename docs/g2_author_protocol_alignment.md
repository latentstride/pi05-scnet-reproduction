## 唯一建议

**先准备一条作者原生 Aloha Fixed H50 基线，以缓存分片 0 的第一个场景 100000 为预先选定样本。** 验证的假设限定为这条场景。冻结模型在作者公开的原生复位、unseen 指令和 H50 查询节奏下，能在原生任务谓词下完成该场。选它是为了先取得可核验的源本体基线，避免把 ARX 映射或局部恢复引入解释。一次成功可以证明冻结策略在本次重建条件下有一个成功实例。它不能量化某个协议因素的独立效果。正常达到 800 动作仍未成功则拒绝这条场景的假设，无法推翻论文的总体成功率。若原安全门禁先拒绝，结果记录为安全终止，完整任务结果不可判定。

CPU 先用已发布 seed、`episode_info`、固定资产/相机配置和同一模型清单核对复位、指令生成和窗口逻辑。冻结 Python 随机状态及生成后实际选择的 unseen 字符串，明示这是重建条件。还缺 **100000 场景的真实复位读回、三相机首帧及门禁兼容证据**，也缺一条作者历史成功回执可作逐值比较。当前 CPU 桩只检查流程，尚未完成该场景的真实复位/渲染对齐。因此**现在没有足够的准入证据投入 GPU**。

如上述输入和安全准入能被验证，完整任务判定确实需要新的闭环推理。届时仅在一次获批 Slurm 分配的同一个共享服务内完成，先核对模型/图形/首个请求与输出的留存，再让原生基线推进。保存同 tick RGB、状态、prompt、采样状态、响应及动作边界。若门禁要求第 50 行前重查或安全停止，记录协议偏离或删失并停止该诊断，不能标成原生 Fixed H50 完整失败。保留安全退出凭证与基础设施异常独立分类；无需另开 GPU smoke 或自动重排队。没有通过准入或只能复刻项目原条件时，结果不值得重复消耗 GPU。

## CPU 复现

[CPU 检查回执](../research/g2/author-protocol-alignment/cpu-check.json)保存了 60 个已锁源码核验、300 个缓存场景筛查、三个空 info 指令池、两次客户端请求哈希及作者循环的模拟查询序号 `[0,50]`。本轮只使用保存数据及纯 CPU 桩，没有重跑碰撞或物理轨迹。第二次的请求哈希是离线重算，缺少独立服务端回显。

```bash
python scripts/g2_author_protocol_audit_cpu.py \
  --protocol "$pinned_protocol_sources" --raw "$saved_exchange" \
  --output "$new_cpu_receipt"
```

`--protocol` 使用已有 [源码锁](../research/g2/protocol-audit/source-lock.json) 的相对目录结构，`--raw` 使用原第二次查询审计保存的目录结构，包含两次查询各三张 RGB、动作、模型启动和 RNG 回执。完整 RGB 留在私有原始证据，公开派生回执不携带私有路径。冻结研究结果与原统一方案按 `ccdf121` 保留，本轮仅增加离线审计。
