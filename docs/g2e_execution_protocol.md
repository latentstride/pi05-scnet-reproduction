# G2-E：原生长窗口执行与 CPU 验收协议

协议 ID：`g2e_native_guarded_prefix_v1`；显式接触模式：`g2e_native_measured_contact_v1`。仅 Aloha 可启用 1、4、26、31；默认原生与 ARX 仍只接受 1、4。没有改写冻结的原始发布包、G1 或 LIBERO。

每次查询仍保存完整 50×14 原始输出，校验全部有限性，按请求 K 取前缀，原关节限位与最大 0.01 的夹爪裁剪限制保持不变；末窗最多补足 300 个动作。每一行交给原生 `take_action(..., qpos)`，沿用原 TOPP、动作完成条件和夹爪力参数，不引入新轨迹控制器、不替换模型观测。

每个真实 `scene.step` 前，使用真实关节/独立两指与当前插值 drive，刷新 FCL 世界。沿实际到 drive 的关节段按 ≤0.02rad 联合检查两臂、手指、托盘、桌面、物块；物块已被真实持有时传播其实测附着变换。接触预测使用原 1mm 扫描步长，不把负闭爪 drive 当成必须穿过物块的刚体终点。预测手指几何仅用于碰撞计算，绝不写回原生驱动。

每步推进后记录实际物块位姿、接触体 ID/名称、接触点、法线、separation、impulse、实际手指与 drive。按原 `ContactLimits` 确认双指连续 3 步有冲量接触；滑移 5mm/5°、双持闭链 2mm/2°、允许接触穿透 2mm、闭合投影 0.5mm 均未放宽。仅手指–物块和物块–支撑面的浅接触可被原规则允许，机器人–托盘/桌面仍拒绝。左手单独持物时禁止提前释放。原生夹爪 drive 范围来自实际 source 设置并保留在 setup，校准手指物理几何仍为 0…45mm、原 1mm 测量容差。

实际 arm 跟踪超过 30mm/10°、限位、碰撞、接触丢失、滑移、时钟异常、非有限值及超时均终止当前试次并执行原 hold/close。正常闭爪被物体挡住时，不用“手指没到目标零”作为跟踪停机依据。已完整执行的动作计入 `executed`，中断中的动作单独保留动作索引和已推进物理步，绝不把整个 K 窗口算作执行成功或全部丢弃。

所有条件共用：300 动作、最多 25,000 物理步（下一步前拒绝）、1150s 合作超时、1200s 进程上限。200 次候选检查后平均候选 CPU 耗时 >0.2s 时停止，作为效率/基础设施结果。进程硬超时由宿主进程组监督器杀死并回收所有后代。各 K 的控制器、安全规则、预算、初态和提示均相同，K 只改变下一次策略查询发生的时机。

每个完整动作记录一帧视频，末态另存一帧；不把 K31 的十来个策略观测帧当作完整任务录像。每次查询的原始 RGB 另存，保持模型输入契约。

模型每个试次重新连接同一服务，使用带确认回执的显式 RNG reset。环境种子 0/1 对应共同查询随机流 20261106/20261107；新 K 的第 n 次查询使用同组同序列噪声，消除前一试次消耗 RNG 的次序混杂。权重、采样步数、图像、tokenizer、norm stats、提示与状态映射不变。JAX key API 已对照固定 OpenPI 源码，真实权重加载/编译仍为 GPU_DEFERRED。

CPU 已覆盖长前缀实际调用、闭爪位于第 24 索引的执行、未启用 guard 的拒绝、ARX 越权拒绝、部分窗口中止计数、hold/close、物理步预算、真实 WebSocket RNG 协议、模型退出不重启、进程组超时清理及缺失试次评分。完整测试日志位于 `results/g2/g2e-20261106-r1-cpu*`，最终项数以验收报告为准。

真实 SAPIEN 3.0.0b1 / mplib 0.2.1 的 CPU FCL 使用源机器人碰撞 URDF、锁定根位姿/关节/手指及任务刚体重建，**零物理步、无 renderer、无模型**。两种初态均通过；两组把托盘移到实际右指处的负例均拒绝。首块冻结场景中，seed0 K26 通过、K31 在索引26拒绝；seed1 K31 通过。静态中位候选耗时约15ms。冻结物块没有随物理运动，因此不能把这些路径检查当作完整动态轨迹；实时 TOPP、接触动力学、加载真实模型后的资源及完整交接成功均为 **GPU_DEFERRED**。

原成功谓词保持不变。另输出实测物理阶段审计：左手单持→双手持有→右手单持→释放，并要求目标托盘有真实支撑冲量。未观察到阶段，不补造为成功；谓词成功和完整阶段证据分别报告。若原谓词提前成立而尚未观察到完全脱离，也不能把释放证据写成已完成。
