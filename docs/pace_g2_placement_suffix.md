# G2 放置段 CPU 修复与复验

从生产试跑第 27,524 步保存的右手独持状态出发，局部放置连续两次通过。每次推进 1,570 个 PhysX 步，2,417 次 FCL 检查零阻断。两次的 25 个计划文件、逐步物理日志和完整 FCL 日志 SHA-256 逐项相同。复验沿用原 5mm/5° 滑移参考和原门禁。冻结版本的 26 份 Python 源码全部与此前验收清单一致。

## 碰撞定位

扫描归档中心反馈参考 episode0 从第 27,434 步至首次托盘拒绝间的所有已保存样本。拒绝发生在阶段 12 的最后下降，右夹爪仍要求闭合，右指 `arx_right_15/link7` 先碰托盘 `target_box_27`，碰撞对未涉及另一只机械臂或物块。

| 证据 | 原参考物理步 | 深度或冲量 | 接触法线 |
|---|---:|---:|---|
| 首个拒绝的规划候选，FCL | 28,145 | 0.155859mm | (0.016355, 0.000012, −0.999866) |
| 原 PhysX 首个非零托盘冲量记录 | 28,157 | 0.066953N·s | 原始归档没有法线 |
| 首个拒绝的实测几何，FCL | 28,160 | 0.000919mm | (0.016221, 0.001014, −0.999868) |

FCL 法线采用保存的右指与托盘查询顺序。诊断 JSON 保存左右侧区分的右指网格顶点及三角面、指与托盘及物块的姿态、预测物体和指位姿、两类 FCL 接触点。归档 PhysX 按接触对变化记录，最近前一条事件在第 27,984 步，包含右指与托盘的分离接触候选，当时冲量为零。原第 28,157 步只有汇总冲量可回读，无法从归档恢复它的逐点法线或穿透深度。

## 局部放置

左臂保持检查点位置。右臂抬升 12mm 并移至托盘上方，使用持物关系规划下降。释放候选以物块最低点距托盘顶面 5mm 为目标。下降前另做张爪预检，执行中每个控制目标和实测物理步分别走冻结门禁。释放后张开至 44mm 并抬升撤离 35mm，额外保持 0.4s。速度、加速度、关节和指限位沿用原规划与执行检查。

生产检查点来自原 CPU 试跑的真实关节、驱动目标、物体位姿和抓持参考。归档未保存关节及物体速度和 PhysX 求解器内部状态，后缀从零速度重建并用三步真实物理确认双指持物，再恢复原抓持参考。验收范围是确定性重建后的放置后缀。另一个独立参考检查点第 27,434 步也完成了放置，耗用 1,350 步。

生产检查点复验中，实测释放时物块底部离托盘 4.984mm。首次支撑冲量发生在后缀第 1,035 步，仅 `box ↔ target_box`，PhysX 法线为 (0, 0, 1)。两次均满足原任务判据和完整落在托盘内的检查，最后物块功能点相对托盘目标的偏差为 (+0.163, −4.047, +0.221)mm。撤离和额外保持均完成。

## 文件

- `scripts/g2_placement_cpu.py` 为独立 CPU 后缀入口。`--production-event` 指向生产验收包的 `selected-events.json`，加 `--skip-diagnosis` 可单独重跑生产状态的放置复验。其余场景和资产参数与原门禁 CPU 入口一致。
- `research/g2/placement-20261106/collision-diagnosis.json` 为首拒绝几何证据。`archived-physx-contact.json` 保留原 PhysX 冲量和最近接触对事件。
- `research/g2/placement-20261106/r3/trajectory.zip` 含可复核的分段轨迹、报告和远端完整日志清单。远端完整原始日志位于项目内 `results/g2/placement-r3-20261106/`。
- `research/g2/placement-20261106/timing-r3.json` 和 `control-calls.csv.gz` 保存原试跑阶段统计和全部 5,506 个控制调用区间。
