# G2 第四轮：接触控制接入与 CPU 证据

后续更新：[第五轮](pace_g2_grip_stage5.md) 已修复下文的双指标量映射阻断；本报告保留第四轮产生时的状态。

日期：2026-11-05。仅 CPU 开发，未申请或提交 G2 GPU 作业。正式 run_lock 未冻结。

## 已实现的行为

- `Trajectory.fingers` 保存有限力位置驱动的命令轨迹，`predicted_fingers` 保存受物块阻挡后的几何预测，实际关节位置独立逐物理步采集。保持夹紧时下一段驱动从已提交的命令继续，不从实测开度重新开始。
- IK 候选和重定时路径通过首次有界手指接触预测检查；仅指定两指/物块与浅层物块/支撑面允许接触，深穿透、手掌、环境、跨臂碰撞继续拒绝。接触数据缺失、非有限值或截断时拒绝许可，并记录可序列化的未知深度。
- ARX 执行器配置 `force_limit`、PD 参数，按真实物理步采集接触冲量及物块/工具关系。持续双指接触且相对位姿稳定后确认持有；滑移或非预期接触丢失立即结束并留证。
- 接触事件中断当前动作前缀并重新采集、查询，窗口4未执行的后缀不自动回放。单次查询最多执行请求窗口，接触边界可以缩短其实际执行长度；此行为必须在窗口消融协议中说明。
- 接收手未确认持有时禁止给出手打开；双持时先保持两臂位置执行释放，测得接触结束后才重新规划撤离。
- 携物碰撞世界由持有手的候选工具位姿预测物块，并检查物块/环境和双持闭链一致性。实际状态检查保留物块实测位姿，不能用刚性携物假设覆盖实测滑移。查询后恢复 FCL 物块姿态和关节状态，不改变物理场景。
- `g2_run_task` 的真实入口仅接受显式诊断接触配置，所有阈值/力参数必须完整提供。正式数据仍拒绝。原 strict 配置仍保留。

## 后续策略查询发现的接口限制

20N提起终点实测左指28.838mm、右指30.293mm，相差1.455mm。物理接触允许独立驱动的两指产生不同位移，但现有 `Grip.read()` 的标量代理合同把超过1mm差异视为 mimic mismatch；按当前代码继续策略观测会拒绝。新增回归明确保留该拒绝，未通过扩大容差或替换实测掩盖差异。因而提起夹具通过不能写成策略闭环通过。

下一项实现应显式定义“独立双指实测→单个策略夹爪标量”的约简：每指物理限位独立检查，保留两指实测与约简残差，按接触状态和标定后的非对称阈值决定是否可输入策略；碰撞几何继续使用两指实际值。需要在相同合同下核对源Aloha和ARX，防止把命令/实测混入不同对照条件。该协议尚未定版。

2026-11-06 质量范围补充：本报告0.72kg是直接PhysX形状构造的负载夹具。原任务`create_box`返回`Actor`后默认把质量覆盖为0.01kg；已在新原生专家回放中实测核对。因此本报告低力滑移结论不直接外推到原任务10g物块，旧失败保留。见 `docs/pace_g2_native_expert_replay.md`。
