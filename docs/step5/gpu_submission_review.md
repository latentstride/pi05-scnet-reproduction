## 最后一次 CPU 定向诊断

只申请一次 `Agent0` CPU 资源，作业 `128123718`，节点 `i03r4n02`，2 CPU、6 GiB、无 GRES，硬时限 10 分钟。使用原发布的 `env.sh cpu` 和 XNNPACK，持久 JAX 编译缓存关闭。复用 `results/step5-fixed-grad-r1.qkqDsi/fixed-input.npz`（SHA-256 `b542bd41d86760076ab4f9b66d4feaacd36de17c0bcec30ef4142c826bf6b77a`）与 manifest（`11282082f0e9606846463538bc6653372e1eaadf34ac3fd5b439a23cb6e40e0a`）。不读新训练样本、不重做数据或底座审计。

唯一目标为 `PaliGemma/llm/layers/mlp_1/linear_lora_b`，FP32、`[1,2,32]`。历史生产伴随图对此叶子的 L2 范数为 0，独立梯度图约 0.199764。它是动作专家最后一层 MLP 输出路径的 64 元素叶子。复用快照的真实 `Observation`、target、权重和 PRNG。保留原前向上下文和 `train=True`，`jax.value_and_grad(argnums=0)` 仅对这一个叶子求导，保留所需的反向依赖。不返回其余梯度和 Optax 范数。每次结果显式 `jax.block_until_ready` 再取回主机计算 SHA-256、有限性、绝对差及相对 L2 差。只在同一可执行图的哈希不同时，才在**同一分配、同一叶子**上补充单核亲和性和单线程对照。

原始执行及脚本位于 `results/step5-last-leaf.kYDr0r/`。`leaf.py` SHA-256 为 `973c37ec6143d1c55701abe56189c1df8e441a8ab0d3cab8c7d3f46e882d0077`。以下是节点中的常规计算命令：

```bash
timeout -k 10 300 bash "$release/scripts/step5_arx/env.sh" cpu \
  "$root" "$out/leaf.py" "$root" "$release" "$snapshot" "$out"
```

作业退出 0，耗时 2 分 36 秒。快照 123 个叶子的原始字节哈希全部匹配 manifest。71 个参数叶子用于重建同一缩小模型的前向模板，已保存的 AdamW 状态通过完整性核对，单叶求导本身不执行 Optax。typed key 的底层数据为 `[2465931498,255383827]`。

## 现有单作业的执行能力

静态检查对象为 `scripts/step5_arx/{train.slurm,env.sh,train.py,model.py}`。

| 阶段 | 现有行为 |
| --- | --- |
| 设备及完整模型 | 校验项目根、代码、数据、环境版本和 checkpoint 快照。CUDA driver 与 JAX 核对单个 RTX 4090。恢复完整 PACE 底座，检查两个图共用的 51 个 BF16 参数及 LoRA A/B 初始化。 |
| 初始损失 | 同一已编译 LoRA 可执行图用相同观测、动作和 PRNG 比较种子初始化与全零 adapter，`initial_loss.json` 保存结果。 |
| 第一、第二次更新 | 独立单步阶段做真实前反向和 Optax 更新，然后丢弃该试步的状态。随后过拟合循环从初始状态重启。前两次过拟合更新已按序消费同一 adapter 与 AdamW 状态，`update()` 每步拒绝非有限 loss、梯度范数、更新范数或无更新。现有日志没有单独、持久的第二步门禁记录。 |
| 底座冻结 | `optimizer_step` 仅对 adapter 求导，优化器矩张量仅覆盖 LoRA，返回状态中无冻结参数更新。加载阶段验证两个图共用底座。GPU 尚无两次更新后的逐值回执。 |
| 显存与停止 | 初始检查、单步、过拟合及正式阶段运行在同一张卡上。已有 allocator 记录。训练异常输出含错误消息、allocator 统计和 Python traceback。只有完成的 Orbax checkpoint 可用于人工恢复。Slurm 使用 `--no-requeue`。 |
| 过拟合与正式训练 | 20 步固定样本先于 400 步训练。过拟合未过现有阈值立即停止。门禁通过后执行冻结 validation，再继续 400 步，定期保存和验证。 |

获准后最小的门禁日志修改是在**现有 20 步循环**中给前两个连续更新各写持久的阶段与结果。保存步号、AdamW 计数 1/2、loss、梯度范数、更新范数和 JAX allocator 当前值与峰值。开始调用前就记录步号。失败时记录异常类和原 traceback、allocator 信息、最近已完成 checkpoint（若存在），并保持原错误退出码。用同一套冻结路径分区校验确认优化器没有覆盖底座。若评审要求 GPU 逐值回执，可逐张量分块校验前后摘要，避免同时保留第二套底座显存副本。两个前导更新仍计入原 20 步，保持原学习率、随机数策略、过拟合阈值和正式训练流程。该修改本轮只评审；不新增独立 GPU 冒烟作业。

## GPU 风险与资源预算

- 当前完整模型尚无已修复路径的 GPU 实际初始 loss、第一和第二次 CUDA 反向、实际 AdamW 更新以及 20 步过拟合结果。CPU 实测使用缩小模型；CPU 和 CUDA 共享 OpenPI 反向图的构造、NNX 和 Optax 路径。
- 此前两张 4090 完整恢复后的 JAX allocator 峰值为约 7.24 GiB 和 7.05 GiB。反向激活、编译与工作区峰值、CUDA scratch 及碎片仍未知。JAX allocator 峰值也不等同于进程在驱动层的总驻留显存。
- 建议审核的一次作业为 `ksagnormal01`、1× RTX 4090 24 GiB、8 CPU、64 GiB RAM、batch 1、6 小时硬时限和至少 16 GiB 可用运行盘。本次只读盘查约有 100 GiB 可用。正式 400 步每 25 步保存，常规 16 份 LoRA/AdamW checkpoint 张量载荷约 8.9 GiB。各门禁耗时和 400 步吞吐待 GPU 实测。
- SCNet 历史费率记录为 `¥3.60/卡时`，原订价回执有效期至北京时间 2026-11-22 15:57:17。以该参考费率，满 6 小时的 GPU 部分预算为 **¥21.60**。该历史回执对应另一份 ARX 推理作业，不是本次训练的授权。未来实际提交前需核对本训练队列报价、核卡比以及 CPU、存储等计费项。账单金额以平台为准。 [SCNet 计费规则](https://www1.scnet.cn/help/docs/mainsite/hpc/advanced-guide/billing-rule/) [仓库已核价的同类 GPU 记录](../robotwin_gpu_acceptance_plan.md)

## 正式收据与例外

`admit_gpu()` 保留现有硬门禁，包括 `cpu_pass`、代码/数据身份与版本、checkpoint 文件快照、磁盘空间及设备检查。先前的结构级 JSON 即使包含 `cpu_pass` 字段，也只证明已记录的结构范围，不能用于当前训练准入。本评审未生成、复用或改写任何 `cpu-receipt.json`，未修改哈希或提交入口。

若未来获明确授权评审正式例外，`CPU_VERIFIED` 必须对应通过的数值验收，`CPU_NUMERIC_EXCEPTION` 应单独保留已知失败、授权记录和一次作业的预算范围。两种状态均校验同一份代码、数据、权重、设备、路径、版本和资源条件。例外只处理 CPU 证明缺口，仍要通过同一分配内所有真实 GPU 数值检查。本轮未实现例外机制，也无 GPU 提交授权。若将来修改门禁日志或收据入口，须重新发布并核对新的代码身份；旧收据的哈希不得改写。

## 提交审核结论

**`CPU_NUMERIC_UNRESOLVED`。当前证据不足以放行第三次 RTX 4090 训练验证，本次例外评审不建议批准。**

两次旧启动错误都有定向修复和真实输入级的 CPU 证据；GPU 完整权重加载曾成功，CPU 真实第一步更新和 Orbax 往返曾通过。静态审查没有发现新的确定性训练源码错误。完整训练第二步的数值不一致仍未解决，最后的单叶诊断只支持跨图差异，无法把风险限定为 CPU。现有正式收据门槛也未满足。GPU 的真实反向、连续更新及峰值显存仍待实测。

CPU 定向排查到此结束。本轮未提交 GPU，未执行 `sbatch`，未改训练源码、模型、数据、阈值或例外机制。若今后另择正式审核例外的路径，须先明确授权并保留全部门禁，不能据本文件启动作业。
