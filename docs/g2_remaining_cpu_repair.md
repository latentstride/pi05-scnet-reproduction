# 剩余 G2：ARX CPU 修复与证据

本轮仅新增独立 CPU 模块和验收证据，没有提交、取消或修改任何 GPU 作业，127081074 的冻结代码与资源配置保持不变。原始 G2 结果、G1/LIBERO 与已经冻结的生产安全门禁均不改写。

四个原始失败端点在更精确的 IK 下仍全部拒绝。修复目标是明确拒绝原因、为失败状态提供有界安全恢复、补上直线关节路径的绕障能力，并完成专家放置段的局部规划；不把危险端点改成豁免，也不把恢复成功写成任务成功。

重试使用原内部容差及更严的 10μm / 0.00057°、0.1μm / 0.000057°；外部工具容差仍为0.5mm/0.05°。原工具空间目标不变时，没有找到合规精确解。两次候选左指压物块、源Aloha代理腕部、目标ARX自碰撞的根因均保留；精度提高未消除它们。

有界进展只允许在非持物自由接近阶段，候选进度固定为1、3/4、1/2、1/4、1/8、1/16；更改目标相对原指令不得超过12mm/1°。此包是旧失败数据驱动的探索性设计，后续统一试验前须固定规则，不能按新试验结果调参。四个检查点的最终偏移均在该包络内，所求每个新端点仍满足原IK与完整QuinticMotion门禁。精确拒绝、候选进度、原/执行工具位姿、轨迹和回代均留证。

源映射失败时，RecoveryCoordinator不会把一个未实现的虚拟位姿直接送进模型。它规划实际ARX回到上次源工具位姿，执行后重采集RGB与关节、验证时间前进，重新映射通过后才允许推理。每试次恢复最多4次，每次失败观测最多一次物理恢复；仍失败则停机。后缀某行被拒绝时，只重新规划并执行此前明确安全的前缀，禁止跳过未执行的中间动作。

新增JointRouter用于原直线路径碰撞、端点本身无碰撞的自由空间段。确定性随机种子20261106、最多384节点，每条边按原≤0.02rad采样，再交给原QuinticMotion完整检查速度/加速度和几何。原终点与手指指令不变；RRT内部节点不计作新的策略动作。持物/释放以及改变夹爪的阶段不允许通用自由空间随机搜索。

真实机器人网格加8mm物理障碍的负例：直线被拒绝，RRT以13节点/39轮、474次边采样找到绕障，最终214个控制点、1个策略动作，终点关节差0，最大速度0.498565rad/s≤原0.5rad/s。第一版较大托盘放置负例的所有终点都已被阻挡，未将其计入绕障通过样本；后续明确改为端点清晰的物理小障碍负例，用来检验路径搜索，而非解决原危险端点。

三条真实专家轨迹共854个记录帧边界，实测几何799通过、55拒绝，分别24/22/9；全部拒绝对为右link7–target_box，没有忽略微小穿透。该检查不声称相邻记录帧之间的连续轨迹通过。

首版放置恢复错误地取了右手刚独持、左手尚未完成释放/撤离的状态，三条均因左指候选压物块而被原规则拒绝。修复为官方专家阶段11结束、阶段12下降开始前的明确语义边界，保持此前抓取/交接不动。此选择不是挑成功种子，也没有重置实际抓持滑移阈值。

三条新后缀均使用：托盘上方额外抬升12mm并平移对准、物块最低点距托盘顶面5mm处下降、预检完整张爪、打开至44mm、撤离35mm。手臂限速/加速度与全部接触阈值保持原值。阶段11以前原专家路径不改。先前同任务seed0的两次真实CPU动态后缀1570步、零FCL阻断且task_success=true仍保留为历史动力学支持，不扩展成新三条后缀的动态通过。

本轮所有SAPIEN/FCL新场景均0物理步、无renderer、无模型、无CUDA，单线程并限制每进程120–300s；没有在登录节点重跑重型PhysX全轨迹。专家归档提供实际q/指/物块；抓持关系只用于静态持物几何。张爪后撤离的“已释放”是明确的规划分支假设，未伪造ContactTracker.observe、冲量或任务成功，结果task_success=null。

新增持久化harness已覆盖原始预测/RGB/计划、模型输入合同、恢复与策略动作分账、错误保留、deadline、hold/close及原有schema导出。源码入口是scripts/g2_remaining_{geometry,router,coordinator,episode}.py；静态复验入口是g2_remaining_{replay,route,expert_audit,placement}_cpu.py。运行中的发布目录没有导入这些模块。

最终完整CPU回归项数与13个合成episode见[验收报告](g2_remaining_cpu_acceptance.md)。本轮初次全量回归发现旧G2-E测试把“未审批”写成永久断言；用户上轮已经授权提交，故仅修订测试为校验准入状态与授权证据一致。未为此改变运行时准入或GPU发布包。
