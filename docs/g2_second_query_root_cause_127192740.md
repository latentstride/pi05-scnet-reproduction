## 四个回答

1. **第二次碰撞目标来自模型服务返回的动作。CONFIRMED。** 第二块首行是已反归一化、绝对化后的关节目标；其左指候选穿透 **15.641 mm**。历史异常中的 **4.736 mm** 属于其后 +Z 修正的 IK 候选，不是未经修改的模型目标。第二块在执行物理步之前被拒绝。
2. **未发现可确认的相机交换、状态排列、统计串用、弧度转换或重复累加增量错误。** 已核对具体数据和变换链，不能只以 14 维一致作为依据。第二次服务端未保存输入回显、归一化中间张量和去噪输出，仍有验证边界。
3. **直接证据更支持“策略在当前项目状态下生成了不可行的接近目标”，而非第二块的控制跟踪或动作解释出错。** 但这不能区分 checkpoint 本身能力不足与项目评测协议/状态分布差异；当前不足以给出唯一最终根因。
4. **下一步只优先做作者成功评测快照的金标输入—输出一致性核验。** 需要原三相机、14 维状态、prompt、RNG 与参考 50×14 响应，以固定权重和变换核对同输入输出。这能隔离服务/协议差异与当前状态下的策略失效。本轮不执行该措施，不生成 GPU 计划或授权。

## 同场景专家与训练分布

复用官方 seed0 密集专家及已成功的 CPU 物理回放，静置物块初始位置与本次**逐值相同**。比较前统一坐标：专家原 `actual_endpose_matrix` 是关节全局框架，转换为本项目 TCP 需要局部 **120 mm** 平移和固定右乘 `diag(1,−1,−1)`。转换在 710 个接近样本上与实测关节 FK 的最大矩阵元素差为 **8.34×10⁻⁷**。这属于表示约定，不是模型关节命令转换；不能把未转换的专家 endpose 与策略 TCP 直接相减。

同一捕获物块/场景中，专家 tick 576、709 的张爪接近端点均通过原碰撞检查。专家预抓取命令 TCP 约为 `[-0.185686,0.200283,0.910001] m`；其接近路径在方位、姿态上明显不同。以实测 TCP 位置搜索专家接近阶段，最近样本仍差 **32.08 mm / 84.05°**，并非匹配状态。因此本轮只将专家用作阶段/几何参照，**不进行跨时间动作标签误差比较，也不声称专家能从当前策略状态动态接续成功**。

已确认的协议差异：本次提示不在公开 `seen/unseen` 列表；场景 seed0、固定 RNG 20261106 与作者评测分片/随机流不同；名义 H50 在第 27 动作修正后提前重查，并非作者无干预 Fixed H50。它们是否造成第二次错误尚未隔离。

公开模型声明每任务 50 条 Aloha `demo_clean`。既有 ZIP 核验已证明本项目专家归档与该公开 `demo_clean.zip` 不能视作逐字节相同的数据；**实际训练 LeRobot 快照、RGB/提示、采样处理与逐样本成员清单仍 UNKNOWN**。没有证据证明选错任务/本体，也不能证明当前样本在训练内或训练外。第二次状态按匹配统计归一化的最大绝对值仅约 **1.0004**；分位数范围不构成训练分布成员检验。
