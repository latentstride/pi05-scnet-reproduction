# G2 三组候选初态及 CPU 发布预检

三组 10g 候选初态通过 CPU 重建检查。每组来自同一个官方 Aloha 专家 episode 与对应 ARX 有限力参考的独立物理归档。同组物块质量、物块位姿和托盘位姿在归档中逐值一致。两侧机械臂各使用自己的基座和关节状态。

复查调用现有 `apply_fixture` 和 `capture_initial`，在实网格场景上读取复位后的状态。三组都通过两本体的初态 FCL 检查，双臂关节读回最大误差为 0。三组 ARX 首帧均通过实际适配器的 Aloha 代理 IK，工具残差最大 0.164mm、0.0053°。三组都留在候选列表中。候选筛查没有读取策略结果。

CPU 复查重建了任务物理场景，Aloha 以实网格代理模型检查，图像使用占位数据。正式评分所需的初态还需在原 PACE 场景加载后回读三路图像、物块质量和位姿，再按同一规则验收并绑定正式 pair_id。

## 诊断配置

三个候选各有 Aloha / ARX × 窗口 1 / 4，共 12 个诊断启动配置。配置使用相同的完整任务指令，明确左手取块、交给右手及放置。G1 只验证了取块提示下的接口，这里的新提示是 G2 启动候选。每个配置限制为 4 动作及 120 秒，供后续检查首次推理和控制。正式试次的动作上限与墙钟上限待核定。

SCNet CPU 容器对全部 12 个配置完成校验，固定 PACE 源码及资产审计通过，回读的配置 SHA-256 与本地清单全部一致。首轮辅助脚本文件名与 Python 标准库 `inspect` 冲突，已改名并复验通过。两轮日志分别保存在项目远端 `results/g2/pair-config-inspection-20261106.log` 和 `results/g2/pair-config-inspection-20261106-r2.log`。本地统一预检 146 项回归及 13 个合成 episode 通过，冻结门禁的 26 个 Python 文件哈希逐项一致。

## 资源测算

用 G1 两次稳定查询中较慢的 3.188 秒、ARX CPU 试跑的规划与控制约 4.663 秒/动作，以及 20 分钟启动开销假设做敏感性分析。取 300 动作为测算上限时，三组四条件在窗口 4 实际平均执行 4、2、1 个动作的情景下，已建模部分分别为 279.4、303.3、351.1 分钟。按此前每分钟 0.06 元估算分别为 16.76、18.20、21.07 元。数值是历史费率情景，另需计入 Aloha 控制、两本体真实渲染与重置、专家对照及发布采样。300 动作和 20 分钟启动开销也都只是测算参数。

只读调度查询确认 gnode39 仍列在 ksagnormal01 分区。该查询只覆盖调度信息。本轮未重新测量该节点的图形栈，也没有获得模型、渲染和规划同时运行的显存证据。下一道发布门槛是核验原 PACE 场景初态和短段吞吐，再冻结正式时间上限、试次清单和唯一入口。当前文件保持诊断身份。
