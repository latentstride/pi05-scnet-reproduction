# G2 锁定运行入口与发布草案

已接通锁定试次、实测初态检查与现有评分 schema。执行入口沿用此前冻结的诊断控制链。正式包装在复位后回读基座、关节、夹爪和任务对象，核对配对及配置哈希，并检查 10g 物块、三路非恒定 RGB 和实测初态 FCL。首次推理前必须完成这些检查。模型清单、归一化统计、参数文件摘要和模型启动回执也纳入核对。

启动模式在同一份锁定配置上最多执行 4 个动作，输出诊断记录，可在综合作业内检查 Aloha 和 ARX 的实际启动与控制。正式模式输出单试次评分记录。汇总要求锁定名单中的每条试次都有终态结果，缺条时输出缺失列表。初态不匹配归类为配对失败，墙钟超时归类为基础设施中断。

唯一入口 `scripts/pace_g2.slurm` 检查发布清单、正式锁及计划哈希，并从 Slurm 回读实际节点和分配时限。在同一分配中运行图形/动态启动、Aloha、ARX、窗口消融、专家和统计阶段。后续阶段依赖实际动态启动门槛，监督器验收要求共享模型只启动一次。

## 验证与发布缺口

- CPU 覆盖初态不匹配时零次策略调用、配置或模型摘要漂移、缺失结果、正式评分 schema 和 roster 约束。测试产生的模拟运行只留诊断记录。
- 批处理入口通过 Bash 语法检查。当前草案无冻结 `run_lock.json`、带实参的远端启动计划或通过状态的发布凭证。
- 预算备选为两组、四条件、8 次策略评测，300 动作仅用于测算。按上一轮历史费率模型，已建模部分 192.9–240.8 分钟。若用 300 分钟做规划上限，历史费率满时约 18 元，余量需覆盖渲染、复位、专家对照和基础设施。缩减样本量、选组规则及硬时限均待核定。
- 在发布前需把固定 G1 模型启动与图形探针、两本体启动检查、逐试次命令和统计组装成可审计计划，验证其路径、依赖和时间分配。批准前的证据见 `research/g2/release-draft-20261106/review.json`。
