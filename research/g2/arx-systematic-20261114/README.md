# 冻结 π₀.₅ → ARX-X5 完整链路根因验收

结论：**FAIL — 现有策略动作尚不能在现有 ARX 实体安全约束下形成稳定抓持。NOT_READY_FOR_GPU。**

这里的 FAIL 是可执行性验收失败：两项真实在线试次和有界 CPU 反事实都没有产生双指稳定持物。它不是“模型所有未执行动作都错误”或“冻结模型不可能迁移”的证明。本轮新增 GPU 作业 **0**；模型推理 **0**；生产控制、部署、碰撞阈值、FK/IK 和实验配置均未修改。

## CPU 反事实：前缀截断是不是唯一原因

均使用归档的原始策略数组，**不调用模型、不使用专家动作、不增加 TCP 修正**。重建真实 q、独立双指位置、驱动目标和物体位姿；历史速度归零，未恢复 PhysX 接触缓存，因此第 2 次查询的回放是明确限定的状态重启，不能声称逐物理步复现原 GPU。

| 案例 | 唯一反事实变量 | 完成策略行 / 新增物理步 | 结果 |
|---|---|---|---|
| 127999421，第 2 次查询 | 原在线接触后重观测边界 | 1 / 1 | 首次单指接触即返回；没有 holder |
| 同一查询、同一状态重启 | 离线保留该动作块，逐行重新规划，并取消首次接触造成的块尾丢弃 | 7 / 330 | 第 8 行仍被 **target_collision** 拒绝，早于第 21 行的明显收爪、第 27 行的半闭；仅 15 个单指接触物理步，无 holder |
| 127999407，第 1 次查询，从真实初态 | 离线保留完整 50 行，逐行原安全检查 | 35 / 5710 | 第 36 行 target_collision 拒绝；动作数和物理步数与 GPU 一致；无接触、无 holder |

拒绝是原 ARX 指—块候选穿透超过原 2 mm 约束；候选诊断及分支保存在各 CPU `receipt.json`，没有虚拟 Aloha 碰撞硬否决。所有执行仍经过原 ARX FK/IK、关节限位、运动限制、路径碰撞、实际每物理步接触、跟踪、持物/滑移/释放约束。所有分支最后 hold，hold 未推进物理时钟。

**反事实排除了“只要延长前缀就足以抓住”的假设。** 接触后频繁重观测确实使闭爪不断后移，但它不是这两项记录中唯一的阻断。它也没有证明候选碰撞预测一定正确地描述可移动物体的后续动态，更不能据此绕过预测检查。

附加的固定端点夹具对照尝试没有生成有效回执（CPU 容器调用退出/超时，日志只有环境启动信息）。它不计入任何 PASS、FAIL 或夹具差异结论；未据此修改模型、映射或控制器，未继续增加尝试。尝试脚本为 `endpoint_cpu.py`，失败日志/状态另行保留。

## 根因结论及修复决定

可确认的近因是 **策略的开爪接近路径在有效收爪之前被 ARX 实体候选几何检查拒绝；接触重观测又把收爪尾段反复后移**。运动学残差和伺服误差远小于抓取位姿与专家的约 2 cm 差异。

尚不能把责任唯一判给模型泛化、名义 TCP 的抓取语义或静态接触预测：三者需要同状态、同目标下的夹具几何/动态证据区分。本次固定端点附加回放没有产出这项证据；成功 Aloha 试次也不是同输入对照。禁止将“未执行的闭爪”解释为“模型没有预测闭爪”，也禁止把真实候选拒绝直接解释为控制器误报。

**生产控制缺陷修复：0 项。** 本次没有获得足以证明某个控制实现错误、且经反事实验证可修复的证据，因此不提交猜测性的前缀、投影、偏置或阈值补丁。已有源代理硬门禁清除及专家全任务验收直接复用。

缺少的具体条件：

1. 一条从真实接近状态到预测收爪目标、保持原 ARX 约束可执行的路径；当前在第 36 / 第 8 行就被阻断。
2. 沿该合法路径执行原策略的双指收爪后，满足现有接触冲量、连续接触及相对滑移规则的稳定持物证据。
3. 夹具接触语义对照，用于判别前述路径问题来自模型目标、名义 TCP/开度映射，还是静态预测对可移动物体的保守拒绝。不能用固定 −Y 8 mm、专家动作或放宽 2 mm 阈值代替这一证据。
4. 若抓持通过，才有条件从新的真实状态请求冻结策略的交接/放置动作。现有归档中没有这部分策略数据，CPU 不能凭空补出。

下一次最小验收仍是 CPU：只在上述首次分歧状态做原目标的夹具/实际动态对照，保留原实体阈值；若证实控制预测错误，才修复该 **ARX 接触运动规划接口** 并回放同一闭爪段，直到稳定抓持成立。当前不批准 GPU，不做参数搜索，不声称已有模型动作足够。
