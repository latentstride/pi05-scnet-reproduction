# G2 作业 127147943 失败根因分析

## 结论与证据等级

当前直接阻碍是策略产生的抓取接近和抓持过程不能推进到稳定交接，ARX 另有源代理几何及目标路径可行性阻断。现有证据尚不能将这些现象归结为单一模型缺陷或单一执行器缺陷。最值得优先验证的是 **Aloha 在闭爪接触仍在就位时建立了持有锚点，持续挤压导致物块相对位姿越限**。这是 `SUPPORTED_HYPOTHESIS`，不是已经确认的门禁错误。

`CONFIRMED` 表示原始事件或确定性数值重建直接支持。`SUPPORTED_HYPOTHESIS` 表示存在证据但尚未隔离因果。`UNKNOWN` 表示缺少必要证据。本轮仅执行 CPU 日志分析和运动学重建。

## Aloha seed0 的首次阻断

**CONFIRMED。** K31 和 H50 首块完全相同，均完成 26 个动作，在第 27 个请求的插值中停止。二者终态关节、工具和手指一致。拒绝记录是 `predicted finger start intersects task block`，左指索引 1，候选深度 **2.081089 mm**，原阈值为 **2 mm**。实际双指开度为 **44.701/44.776 mm**，候选驱动为 **44.822/44.822 mm**，尚未发出左闭爪请求。记录的候选臂插值比例为 1，检查发生在物理推进之前。

`g2_native_backend.NativeBackend._before_step()` 将实际关节和原生驱动送入 `g2e_native_guard.NativeGuard.candidate()`。后者调用 `g2_contact.ContactWorld._project_fingers_at_object()`，在候选臂姿下扫描手指。错误中的 “start” 指这次扫描起点，不能解释为实测当前状态已经穿透。K4 同样完成 26 个动作后触发该类拒绝。

**CONFIRMED。** 从冻结源专家 `expert/seed0/runtime-trace.npz` 还原的命令序列是张爪接近、张爪到达预抓取姿态、保持臂姿闭爪，再抬升。预抓取命令 TCP 为约 `[-0.185686, 0.200283, 0.910001] m`。策略拒绝前实测 TCP 为 `[-0.229870, 0.139236, 0.952313] m`，相距 86.425 mm、姿态差 87.954°。这是接近阶段与专家预抓取端点的空间参照，二者并非同一时间或相同机器人状态，因此不能当作模型预测误差。专家 spawn 的 XY 与本轮物块初态一致到微米量级，spawn z 为 0.842 m，本轮静置读回约 0.840001 m；spawn 与静置状态分别记录。

**SUPPORTED_HYPOTHESIS。** 策略以不同的接近姿态进入物块边缘附近，随后原生插值与门禁发生冲突。原生链直接消费 qpos，经作者控制接口插值，没有调用 ARX 的 FK→IK 和修复规划。故该次拒绝不能归给 ARX 规划器。

**UNKNOWN。** 当前完整日志没有保存该候选的 FCL 接触法线和碰撞见证点，也没有同一状态下替代安全路径的对照。不能仅凭超限约 0.081 mm 判为误拒绝，不能证明原候选在真实动力学中合法，也不能证明模型最终抓取目标本身无解。PR #3 已有历史 FCL 重建，属于旧作业，本报告不将它当成本次独立重放。

接触量是每个手指接触点的冲量模长求和后除以约 4 ms，不能直接称作驱动器夹持力，不能据此拟合摩擦系数。两条轨迹开始左持时仍有非零桌面接触冲量，终止帧该项为零。停止时物块中心 z 为约 0.841702 / 0.840998 m，仍接近初态高度。

**CONFIRMED。** 两个区间内原生指驱动均无开爪增量，实测手指受物块阻挡停在约 30 mm，驱动继续向内。停止时双指仍有非零接触冲量。因此这些日志不支持“闭爪没有执行”或“主动开爪”作为这两次滑移的解释。瞬时 TCP 跟踪峰值分别约 3.085 / 3.178 mm，未触发原跟踪保护。

**SUPPORTED_HYPOTHESIS。** 滑移与持续闭爪时的物块平移、转动相伴。尤其 H50 中，世界工具运动很小，物块在接触内重新就位的贡献值得优先检查。将物块数学上冻结于首持姿态，仅代入记录的工具运动，得到锚点平移差 0.672 mm；K31 为 1.978 mm，均低于 5 mm。这是对已记录运动的几何分解，不是物理反事实仿真。

`ContactTracker.observe()` 以连续三个双指接触样本建立持有参照，并在后续保持原参照检查累计漂移。源专家记录则有固定臂姿的 300 tick 闭爪段，再进入抬升。两种时序差异支持检查“接触确认是否早于抓持就位”。源专家是命令参照，本轮成功 ARX 专家有另一套受限力控制器，不能将它们直接当作同控制器下的因果对照。

**UNKNOWN。** 原生驱动力与接触合力的精确对应、摩擦锥余量、求解器与接触几何对漂移的贡献、物块是否会继续失稳仍无法确认。保持 5 mm/5° 原保护，现有证据不足以把该停机认定为误报。

## 唯一优先验证假设与最小方法

优先检验 **闭爪就位过程与持有锚点建立时序不一致，是原生 seed1 提前停止的主要原因**。新证据是两个真实长窗口中驱动持续闭合、接触冲量增大、工具移动较小，而物块相对姿态率先越限。PR #3 仅指出历史滑移贡献未知，本次用完整物理流量化了这一顺序，并独立验证原停止 tick。相比继续改窗口，这个假设能区分控制/接触问题和后续手腕动作问题。

最小验证应先采用 **无渲染 CPU PhysX 重放**，使用冻结资产、原始初态和完整接触前驱动前缀，从初态重新建立动态状态。重放必须先复现原持有 tick、停止 tick、开度和相对漂移，不能只设置终态 qpos 来冒充等价物理状态。

在复现成功的状态上，仅比较原始驱动续段与固定手腕、继续原始闭爪驱动的短分支，保持安全保护、摩擦、质量、夹爪参数和阈值一致。两分支均到原停止 tick 或原安全停机即结束，记录接触冲量、物块漂移、候选深度和首次锚点时间。另用同一日志离线计算相对关系是否在闭爪过程中趋于稳定，作为状态机诊断，不改变现场持有判定。

若固定手腕仍复现同类漂移，则削弱“大幅手腕运动导致滑移”的解释；若仅原动作分支漂移，支持姿态/时序贡献。两种结果仍不能单独证明摩擦参数错误。若 CPU 无法重现原生前缀，必须先定位重建差异，不能用该反事实指导放宽保护。本轮完成的是确定性日志重建，**尚未运行这项新的动力学分支对照**，不包含 GPU 申请或授权文件。

该假设主要检验 seed1，不能承诺同时解决 seed0 和 ARX 几何阻断。若被否定，应据结果收缩解释，不把所有失败重新包装为同一原因。

python scripts/g2_job127147943_attribution.py "$raw_dir" /tmp/g2-attribution-recomputed
