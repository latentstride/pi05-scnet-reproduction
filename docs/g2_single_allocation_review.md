# 唯一剩余 GPU 综合验收审查

候选协议最多一次分配、一个共享模型服务、两个锁定初态、14 个试次。沿用任务、checkpoint、初态、提示、原成功谓词及碰撞与物理阈值。长窗口只用于 Aloha。ARX 保持已经验证接口的 K4。

|执行顺序|条件|种子顺序|硬上限/次|
|---|---|---|---:|
|1–2|Aloha K31，启用修正保护|1，0|1200 s|
|3–4|ARX K4，恢复与 RRT|0，1|2600 s|
|5–6|Aloha K26，检验真实接触与滑移风险|1，0|1200 s|
|7–8|Aloha K4，同窗比较锚点|0，1|1200 s|
|9–10|ARX 专家与放置后缀，独立诊断|1，0|2200 s|
|11–12|ARX K4，仅有界恢复|0，1|2600 s|
|13–14|ARX K4，原精确映射基线|1，0|2600 s|

K31 和 K26 是历史上进入实际左闭爪的两个条件。K4 保留同窗对照和原生短窗基线，K1 已有失败信息且移出名单。提前安排主要 ARX 诊断，避免重复低进展条件耗尽分配。K26/K31 的结果与 K4 比较可以描述原生执行窗口，不能作同窗迁移比较。ARX 恢复和 RRT 的消融在相同 K4 下进行。专家用于约束、接触和路径上限诊断，结果单独统计。

Aloha 和 ARX 按本体、种子分别核对真实资产、初态读回、当前几何和模型输入合同。ARX 还需代理映射成功，专家需额外通过现场阶段切换。原生谓词失败与 ARX 可安全诊断是独立判定。跨本体表现的科学结论要求同窗原生与 ARX 均有同等物理序列证据，并报告仍存在的控制器和映射差异。单边缺失、原生无完整序列、不同窗口及运行条件不可直接作有效迁移成功率对照。

候选路径拒绝终止当次诊断。实测危险状态、模型或试次进程中断触发停止，未运行试次保留明确原因。每个试次需有足够剩余时长覆盖完整硬上限。不得替换种子、重试或重启服务。两种子是分析单位，预测帧和物理步仅用于诊断。分列任务谓词、物理交接序列、候选拒绝、实测保护、基础设施失败和 not_run。

试次硬上限合计 27,200 秒，图形 300 秒、共享模型及现场准入 1,900 秒、统计 180 秒、清理 120 秒。执行预算 29,700 秒（8 小时 15 分钟），分配硬上限 34,200 秒（9 小时 30 分钟）。1 张 4090、4 CPU、32 GiB。昆山共享集群 4090 当前目录价为 ¥3.60/卡时，预计 ¥29.70，硬上限 ¥34.20。目录页同时显示划线价 ¥7.00，批准文件须绑定届时仍有效的报价证据。 [SCNet 商品详情](https://www.scnet.cn/ui/mall/detail/goods?type=base&goodsId=821418588551249920)

## 发布候选

- 候选包含 14 个按种子、初态读回、提示、随机数和窗口锁定的配置，绑定原 checkpoint、资产、运行时源码和原始专家轨迹的哈希。专家二进制轨迹只纳入本地候选。
- 图形和共享模型检查在同一 allocation 开头执行。启动后按本体和种子检查资产、渲染、实测几何及输入接口。候选或代理映射拒绝只阻断相应试次。专家可在同种子实测几何准入后独立运行，仍须在同一场景观测到双持和右手单持后才能切换到放置。
- 放置在现场检查接近、下降和打开。下降前预检打开轨迹，实际释放后撤离并经过 0.4 秒仿真稳定期。全程沿用生产碰撞门禁，结果调用冻结任务谓词。
- 保留图形、模型阶段、GPU 显存、每个准入、每个试次及停止回执。原安全门禁继续中止实测危险、跟踪超限和失步。共享服务异常和超时触发清理并保留未执行行。统计按两个种子逐对报告，区分任务谓词和实测物理证据。
- 滑移或意外双指接触丢失立即中断当前控制。只有同一物理步的实测关节、跟踪和碰撞检查均通过，且保持、场景关闭及试次进程组清理成功，才记为 `controlled_contact_stop`。下一试次从新场景重新核对初态与几何，证据缺失或确认有危险时停止整场。
- CPU 审阅可用 `python3 -B scripts/g2_final_deploy.py <candidate> --verify` 校验完整包。未来获批后，allocation 内的 `pace_g2_final.slurm` 使用 `G2_FINAL_RELEASE` 和 `G2_FINAL_APPROVAL`。批准文件绑定候选清单、节点、有效报价证据，首次成功准入后仅能使用一次。候选始终记录 `submission_allowed=false`。

CPU 回归和模拟服务证明配置、状态隔离与异常停止。真实渲染和模型首次推理、Aloha 长窗实测、ARX 恢复及两份专家轨迹的现场闭环仍需同一次分配内验证。历史 G2-E 维持 0/8。

启动复核发现旧 macOS 压缩包在 Linux 解包后生成额外元数据文件，严格清单校验会立即拒绝。新包按清单逐文件归档，并向干净模型容器显式传递禁写字节码设置。集群六项 CPU 部署检查和运行后再次验包均通过，完整证据见 `research/g2/final-cpu-review/startup-verification-20261107.json`。作业 127117141 使用了 `candidate-release-startup-final-20261107`。

作业 127117141 首个准入探针通过，第二个探针在场景准备阶段耗尽 145 秒硬上限，14 个试次均未执行。修订版先预留全部试次硬预算、统计与清理时间，再将实际剩余启动时间按未完成探针数分配。每个探针记录场景创建、实测准入、推理、关闭的阶段进度和耗时。任一危险或超时仍按原规则终止整场。计划 29,700 秒为名义预算，启动可使用分配内余量，34,200 秒硬上限及 ¥34.20 上限保持一致。
