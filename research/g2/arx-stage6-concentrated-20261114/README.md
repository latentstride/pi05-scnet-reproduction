# 阶段六集中攻关

本轮复现两个历史碰撞事件，修复已观测接触反复截断动作块的问题，并在原关节路径上增加可安全执行的分段。冻结 π₀.₅ 及其输入、目标与 FK/IK 使用原定义。实测及分段执行的 ARX 碰撞约束保持原 2 mm。整个试次的策略抓持和任务成功仍待验证。

| 阶段 | 已有验收 | 留存问题 |
|---|---|---|
| 1 官方复现 | 3 个 LIBERO 任务、各 5 个初态，15/15 | 仅作为功能性基线，范围小于官方完整 benchmark。[验收](../../../acceptance_report.md) |
| 2 跨本体选型 | Aloha-AgileX、ARX-X5、RoboTwin handover_block 已固定 | 同 seed 或同数据 episode 不保证场景一致。Aloha 成功试次和两项 GPU 的物体初态、提示词和 RNG 不同。[选型与约束](../../../docs/pi05_cross_embodiment_feasibility_audit.md) |
| 3 数据处理 | 100 条、23,814 帧和 95,256 张图像 | 官方样本缺显式时间戳，点云为空。保留重复及静止阶段，采用帧索引，统计需显式选择按帧或按轨迹。[全量证据](../../robotwin100_course/REPORT.md) |
| 4 动作坐标统一 | 已正式验收。两个方向几何筛查有解 47,541/47,628 | 87 个反向目标在有限搜索中未解。名义 TCP 对齐与夹具实际接触等价属于不同验收项。[正式验收](../../../docs/g2_stage4_acceptance_20261112.md) |
| 5 微调 | 跳过 | 冻结已部署模型。 |

原 Aloha H50 3/3、PACE 2/3 复用，新增 Aloha GPU 为 0。两种本体各 50 条专家的归档指令都依次出现左闭右开、双闭、左开右闭，见 [专家命令统计](expert-comparison.json)。该统计用归档显示数据中的采样帧和夹爪命令，接触及持物以物理回执判定。既有同场景 ARX 专家已完成 28,100 步并达到任务原判据，可用于阶段参照。

| 历史失败点 | 固定物块、同名义 TCP，Aloha / ARX 实际网格最大穿透 | 动态证据 |
|---|---:|---|
| 127999407 第 1 次查询第 36 行 | 0.494 / 2.490 mm | 夹具差异足以使固定端点跨过原 2 mm 约束。新版从最后安全快照推进 43 步至实际重观测边界。 |
| 127999421 第 2 次查询第 8 行 | 2.493 / 4.484 mm | 同一 CPU 最后安全快照下两具手指都出现超过 2 mm 的静态重叠。动态在线门禁反事实执行第 8、9 行，230 步内物块平面移动约 11.5 mm，第 10 行仍在 2 mm 停止。保留原检查的分段回放随后执行到第 50 行。 |

第 2 次查询的固定状态取归档动作从第 1–7 行连续 CPU 回放得到的快照。它与原 GPU 重观测轨迹有不同接触历史。这个实验隔离夹具与固定物块假设。关闭夹爪后深重叠不等于实际穿透，因为实物会移动，力限位也会阻止实际手指达到自由空间命令位置。夹具造成的约 2 mm 差异有直接证据，但没有能支持通用 TCP 补偿的证据。模型在当前归档动作序列中可推进至闭爪，但历史序列的完整闭环可执行性未获证实。

旧端点运行曾停在 Python 入口前。采用非交互 shell、清理启动环境、隔离 CPU 子进程标准输入后，两个端点批次成功运行，输出阶段和退出码。旧传输未提供足够证据定位到唯一的 shell 故障。新增端点入口支持指定行、保留未知穿透值并为 Python 内部失败输出阶段及堆栈。原归档保留原样。实际复现快照、真实网格及各行回执位于 [inputs](inputs/) 和 [endpoints](endpoints/)。

控制修复让已被当前查询观察到的接触继续逐行检查。首次接触、新受手接触及持物/释放切换仍建立新观测边界。发生特定指块规划拒绝时，取原 IK 候选上可执行的安全前缀，对该段重新执行完整路径检查和重定时。物理执行继续使用原实时检查，原行还可从新实测状态重规划，累计受同一行动时限约束。运动段与策略行分别计数。原始策略数组和实际分段轨迹分别保存。限定在无持物的接近阶段使用这个修复。没有从专家替换任何策略输出。

两处接口试验来自归档最后安全状态。第 36 行推进 **43 步**，第 8 行推进 **1 步**，均因实际首次单指接触停止并生成新的合规请求。CPU 使用替代 RGB 验证请求结构，双臂、夹爪和物块状态来自 PhysX。真实 RGB、新观测上的冻结 π₀.₅ 推理，以及后续在线任务结果均为 **GPU_REQUIRED**。

使用本次生产规划器的独立归档反事实完成原第 **8–50 行**，共 **101 段、6,330 步**。左夹爪最小实测开度 0.00432，单指接触共 1,099 步，双指同时接触及稳定持物均为 0。物块相对起点横移 136.0 mm、下落 70.0 mm。第 27 行实测开度已降至 0.492，此时物块已被推离且无指物接触。现有归档尾段稳定抓持验收为 **FAIL**。独立的分段回放也完成相同行范围且只产生单指接触。

真实 ARX 腕部障碍负例在动作及物理步均为 0 时拒绝，FCL 碰撞对与深度见负例回执。定向回归 65 项通过。全量本地发现 321 项，27 项报错、3 项跳过、0 项断言失败。报错来自本工作区未包含的历史专家回执、原始轨迹及源文件。

继续评估的依据是专家已证实任务可行、两处控制阻断有可复核的 CPU 执行进展。若配对 GPU 试次在真实新观测后持续只能形成单指接触，或正确闭爪后重复无法建立持物，则现有策略目标或夹持表示需要改变，继续调整窗口或碰撞阈值没有依据。若持物建立而后续失败，依据实测第一个阶段分歧检查交接/放置接口。

复核归档可直接运行本目录的 `verify_physics.py` 和 `verify_candidates.py`。复跑端点需要原 CPU PhysX 环境和审计资产，并将 `scripts` 及 `research/g2/final-system-review` 加入 PYTHONPATH。两个输入快照在 `inputs/`。分别用 `scripts/g2_arx_endpoint_cpu.py INPUT AUDIT ASSETS NEW_OUTPUT --rows 35 36 49 50` 与 `--rows 1 7 8 21 27 32 50`。动态模式由本目录 `production_cpu.py INPUT AUDIT ASSETS NEW_OUTPUT --first-row 36 --mode interface` 运行。第 2 查询使用 `--first-row 8`，并分别选择 `interface`、`archived_tail` 和 `negative`。使用新的输出目录，保持已归档原件的哈希。
