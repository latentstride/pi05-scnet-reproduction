## 最值得做的一项实验

**同一 Aloha 场景上的配对闭环窗口对照，Fixed H50 对 K31。** 先按公开评测入口统一两组的观测编码、指令抽样和缓存重置，然后只改变窗口。H50 是作者公开基线，并且在冻结的 164 个历史块中保留了全部 13 个含右闭爪的块，K31 历史运行没有做到完整接管。该选择用于鉴别执行时序，H50 的闭环成功与安全仍待测。 [作者基线][paper] · [原始块重选](../research/g2/protocol-audit/metrics.json)

1. 两组使用同一冻结权重、归一化、资产、共同初态、同一条上游 `unseen` 指令、相同 RNG 流、相同控制接口、相同动作/墙钟上限及全部现行安全阈值。建议从评测缓存分片 0、1 各取第一条（100000、200000），先核对初态可准入与首块哈希一致。作为小规模诊断，保持项目安全门禁，两组共享同一执行链。
2. 每场景各运行两条件，条件顺序在场景间交叉。每个 trial 依次记录原块、计划前缀、实际请求、驱动、实测 qpos/工具位姿、夹爪、物块、候选对和首个停止事件。原始任务谓词与左持、双持、右持、释放/托盘支撑分开判定。依冻结安全规则停机，预算内未执行项目保留为未运行。
3. 以配对结果判断新窗口是否让右闭爪穿过真实执行链并达到右单持。如果两个条件都在同一候选/接触阶段停止，证据将把下一轮定位到那个阶段。如果原生确实完成任务，再以这套可比场景和观测定义进入 ARX 映射诊断。四条结果不估计总体成功率。
4. 只提出实验设计。历史 `127081074` 的八项批次用约 61.5 分钟、共享模型与启动约 12.8 分钟。按均值外推四项为约 44 分钟，未计 H50 和新缓存场景差异，只用于量级参考。实际预算需评审批准；本轮交付不包含新执行实现或资源申请。

## CPU 复现与证据边界

在仓库根目录，使用已有 Python 3.10+、NumPy 和 SciPy。以下命令只下载锁定的小型公开源码、manifest、norm stats、场景列表和目录元数据。它读取仓库已有证据并把新结果写到临时目录。分析实际运行使用 NumPy 2.3.5、SciPy 1.16.3、h5py 3.15.1。该依赖组合不替代作者固定评测环境。

```bash
audit_dir=$(mktemp -d)
python scripts/pi05_robotwin_audit.py --upstream-dir "$audit_dir/upstream" \
  --fetch-upstream --output "$audit_dir/metrics.json"
```

完整复算可另传 `--sample-dir <官方六个已抽取的HDF5所在目录>` 和 `--recheck-official-zips`，后者通过 HTTP Range 读取目录和三个小 ARX PKL 并验证对应 14 维序列。样本目录结构和抽取工具见[样本清单](../research/robotwin/sample_manifest.json)与[采样脚本](../scripts/sample_robotwin_archives.py)。在私有完整研究目录内可加 `--expert-details`，根据已冻结哈希的 `expert-workspace-20261106-r2/episode{0,1,2}.json` 复算逐帧 IK 极值。公开仓库可复算预测/窗口/事件、资产和几何计数，缺原始 HDF5 或私有逐帧文件时，对应明细字段留空或省略。
